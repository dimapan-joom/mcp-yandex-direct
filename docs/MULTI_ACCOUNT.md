# Несколько рекламных аккаунтов

Один процесс сервера умеет работать с несколькими аккаунтами Яндекс Директа, **у каждого из которых свои ключи доступа** (отдельное OAuth-приложение). Нужный аккаунт выбирается параметром `account` в каждом вызове инструмента.

Так сделано вместо «по серверу на аккаунт»: каждый сервер регистрирует полный набор инструментов, поэтому пять аккаунтов дали бы пятикратное дублирование в контексте модели, и она на каждом шаге угадывала бы, к какому серверу обращаться.

## Настройка

Переменные окружения именуются по схеме `YANDEX_ACCOUNT_<АЛИАС>_<ПОЛЕ>`. Алиас — латиница, цифры и подчёркивания; регистр в имени переменной любой, внутри сервера алиас приводится к нижнему.

```json
{
  "mcpServers": {
    "yandex-direct": {
      "command": "npx",
      "args": ["-y", "mcp-yandex-direct"],
      "env": {
        "YANDEX_ACCOUNT_MAIN_CLIENT_ID": "id приложения",
        "YANDEX_ACCOUNT_MAIN_CLIENT_SECRET": "пароль приложения",
        "YANDEX_ACCOUNT_MAIN_REFRESH_TOKEN": "refresh-токен",
        "YANDEX_ACCOUNT_MAIN_DESCRIPTION": "Основной аккаунт",

        "YANDEX_ACCOUNT_SHOP_CLIENT_ID": "id приложения",
        "YANDEX_ACCOUNT_SHOP_CLIENT_SECRET": "пароль приложения",
        "YANDEX_ACCOUNT_SHOP_REFRESH_TOKEN": "refresh-токен",

        "YANDEX_DEFAULT_ACCOUNT": "main"
      }
    }
  }
}
```

### Поля аккаунта

| Поле | Обяз. | Описание |
| --- | --- | --- |
| `_CLIENT_ID` | да | ClientID OAuth-приложения. |
| `_CLIENT_SECRET` | да | Пароль приложения. |
| `_REFRESH_TOKEN` | да | Refresh-токен; сервер сам обменивает его на access-токен. |
| `_TOKEN` | — | Статический access-токен вместо трио. Протухает, поэтому не рекомендуется. |
| `_LOGIN` | — | `Client-Login` по умолчанию, если аккаунт агентский и нужен один клиент. |
| `_DESCRIPTION` | — | Пометка, которую показывает `list_accounts`. |

Задавать нужно либо все три поля трио, либо `_TOKEN`. Частично заданное трио — ошибка старта, а не тихий откат к статическому токену: полусконфигурированная авторизация должна падать сразу, а не через несколько недель без присмотра.

### Аккаунт по умолчанию

`YANDEX_DEFAULT_ACCOUNT` **обязателен, если аккаунтов больше одного**. Без него сервер не стартует.

Это сделано намеренно: вызов без явного `account` может оказаться записью (изменением ставки, бюджета, остановкой кампании), и уйти он должен в предсказуемый кабинет, а не в случайный.

Неизвестный алиас в параметре `account` — тоже ошибка, причём до обращения к сети. Молчаливый откат на аккаунт по умолчанию означал бы, что запрос подписывается ключами не того рекламодателя.

## Один аккаунт

Для одного аккаунта многоаккаунтные переменные не нужны — работает прежняя форма:

```json
"env": {
  "YANDEX_OAUTH_CLIENT_ID": "id приложения",
  "YANDEX_OAUTH_CLIENT_SECRET": "пароль приложения",
  "YANDEX_OAUTH_REFRESH_TOKEN": "refresh-токен"
}
```

Такие ключи становятся аккаунтом с алиасом `default`. Статический `YANDEX_DIRECT_TOKEN` тоже поддерживается.

## Как этим пользоваться

1. `list_accounts` — список алиасов и какой из них по умолчанию. Работает локально, в API не ходит и баллы не тратит.
2. Любой инструмент с параметром `account`: `get_statistics` с `account: "shop"` вернёт статистику именно этого кабинета.
3. `list_agency_clients` — если аккаунт агентский, отдаёт логины его клиентов. Дальше логин передаётся параметром `login`; он ортогонален `account`: `account` выбирает, какими ключами подписан запрос, `login` — какого клиента внутри аккаунта касается.

## Валюты

У аккаунтов может быть разная валюта. Сервер отдаёт суммы в валюте аккаунта и не конвертирует их — складывать расход разных аккаунтов в один итог без пересчёта нельзя.
